# SonicKit 官网预览与上传

本文件夹是可独立上传的官网源码仓库：纯 HTML、CSS、JavaScript，包含产品 README 和同一套 `images/`。不包含桌面客户端或服务器源码、数据库、模型、设置、密钥或用户素材。

## 本地预览

在当前 VS Code 工作区按 **Ctrl+Alt+P**，或双击 `Start-Preview.cmd`。预览地址为 **http://127.0.0.1:5173**；保存后刷新浏览器即可查看修改。终端按 Ctrl+C 停止预览。

预览只需要 Python 3，无须 Node、npm 或构建。重复运行会复用同一目录的预览服务；其他程序占用端口时明确提示，不关闭其他进程。只监听本机，不对局域网开放。

当前电脑已添加 VS Code 用户快捷键。迁移到其他电脑时，在「首选项：打开键盘快捷方式(JSON)」中加入以下对象；文件夹自带的 `.vscode/tasks.json` 可在独立打开本文件夹时直接使用：

```json
{
  "key": "ctrl+alt+p",
  "command": "workbench.action.tasks.runTask",
  "args": "SonicKit Web: 预览官网",
  "when": "resourcePath =~ /[\\\\\\/]SonicKit(?:-Web)?([\\\\\\/]|$)/i"
}
```

## 上传 GitHub

将 **`SonicKit-Web` 文件夹里面的内容**上传到仓库根目录，不要再包一层同名文件夹。已有仓库只更新对应文件，保留其他无关文件。官网与 README 共用 `images/`，替换截图时只维护这里一份。

```text
仓库根目录/
  index.html
  styles.css
  app.js
  releases.js
  README.md
  images/
  _headers
  robots.txt
  sitemap.xml
  Start-Preview.cmd
  tools/
  tests/
  .vscode/
```

软件包另外上传到 **`ChatTMD/Sonickit` 的 Releases**，官网源码与软件发行文件共用同一个 GitHub 仓库即可。GitHub 自动生成的 `Source code` ZIP 是官网源码，不作为软件便携版。

## Cloudflare Pages

在 Cloudflare 的 **Workers & Pages → 创建应用 → Pages → 导入 Git 仓库**中选择上述仓库：

| 配置 | 值 |
| --- | --- |
| 框架预设 | None |
| 生产分支 | `main` |
| 构建命令 | `exit 0` |
| 构建输出目录 | `.` |
| 根目录 | 仓库根目录 |

本网站不需要运行服务器、绑定 Python、配置环境变量或填写令牌。`tools/preview.py` 只供本地预览，不在 CF 上运行。部署成功后先使用 CF 提供的 `*.pages.dev` 地址检查页面。

**域名现在不用绑定。** 页面部署成功后，在该 Pages 项目的「自定义域」中添加 **`www.sonickit.top`**，按 CF 提示确认 DNS。若 `www` 仍有旧隧道记录，只处理 `www` 的冲突记录；保留账号后端 **`api.sonickit.top`** 的隧道与 DNS。无需把官网接入账号服务，也无需开放服务器 8080 端口。

必须先在 Pages 项目中添加自定义域，再按提示配置 DNS，不要只手工改 CNAME。参见 [Cloudflare 静态 HTML 部署](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/)及[自定义域](https://developers.cloudflare.com/pages/configuration/custom-domains/)。

## 最新版本下载

在 [ChatTMD/Sonickit Releases](https://github.com/ChatTMD/Sonickit/releases) 创建正式发行版，例如标签 `v0.2`，上传项目打包生成的：

- **`SonicKit-0.2.exe`**：安装版。
- **`SonicKit-0.2.zip`**：便携版，完整解压后运行。

保持 `SonicKit-版本号.exe / .zip` 的名称，并将该正式发行版设为 Latest。官网直接读取 [GitHub latest release API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)，自动更新四个下载按钮的版本号和下载地址；每次普通点击重新检查最新版本，不需要修改 HTML。两个格式独立匹配，只下载该发行版实际上传且非空的对应文件，不会混用旧版或源码 ZIP。

没有可用文件、API 限流或网络失败时，页面初始外观不显示发布状态、不隐藏下载按钮；只在点击无法取得文件时给出 GitHub 发行页入口。不在页面中伪造版本号，不使用任何 GitHub 私有令牌。`releases.js` 集中维护仓库和文件匹配规则。

## 展示素材

10 张功能截图尺寸均为 1440 × 900，来自既有公开展示材料，使用真实控件及隔离演示数据渲染。文案、栏目名、草稿、封面和测试音频均为演示素材；音色卡片为虚构条目，字幕为手写示例，不代表模型实际生成或识别结果。模型页保留演示环境的安装状态，局域网服务未开启。

## 检查

`python tests/check_site.py` 检查 HTML、本地链接、共用图片、预览隔离及配置。有 Node 时可运行 `node tests/releases.test.mjs` 检查发行匹配，再运行 `node tests/page.test.mjs` 检查实际页面脚本的下载按钮与截图选择处理；后者使用 DOM 替身，不代替浏览器视觉验收。官网运行和预览不依赖 Node。
